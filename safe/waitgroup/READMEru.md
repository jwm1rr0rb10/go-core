# safe/waitgroup

[English version](README.md) · [← safe](../READMEru.md) · [← go-core](../../READMEru.md)

`sync.WaitGroup`, который сообщает о неправильном использовании, а не
ломается, показывает значение счётчика и умеет ждать с контекстом или
таймаутом.

```go
import "github.com/jwm1rr0rb10/go-core/safe/waitgroup"
```

## Возможности

- **Ошибочный вызов отклоняется, а не применяется.** Если `Add`/`Done` увёл бы
  счётчик в минус (или переполнил `int32`), вызов возвращает ошибку и
  оставляет счётчик как был, так что группа продолжает работать. С
  `WithPanicOnMisuse` такие вызовы паникуют.
- `Go(fn)` — как `sync.WaitGroup.Go`.
- `WaitContext(ctx)` и `WaitTimeout(d)`.
- `Count()` читает счётчик.
- Без блокировок: только атомики, ~34 нс на пару `Add`+`Done`, ноль
  аллокаций. Нулевое значение готово к работе.

## API

| Идентификатор | Назначение |
|---|---|
| `NewWaitGroup(opts...)` / `var wg WaitGroup` | Создание |
| `Add(delta) error`, `Done() error` | Изменение счётчика с проверкой |
| `Go(fn)` | Запустить `fn` в отслеживаемой горутине (паника не перехватывается; при необходимости оберните в `safe.Func`) |
| `Wait()` | Ждать, пока счётчик не станет нулём |
| `WaitContext(ctx) error` | Ждать или вернуть `ctx.Err()` |
| `WaitTimeout(d) bool` | `true`, если группа успела завершиться |
| `Count() int` | Текущее значение счётчика |
| `WithPanicOnMisuse()` | Паниковать вместо возврата ошибки |

## Использование

```go
var wg waitgroup.WaitGroup
for _, job := range jobs {
	wg.Go(func() { process(job) })
}
if !wg.WaitTimeout(30 * time.Second) {
	slog.Warn("workers still running", "count", wg.Count())
}
```

## Замечания

Правило `sync.WaitGroup` никуда не делось: `Add` с положительным значением,
начатый при нулевом счётчике, должен произойти раньше `Wait`. Если
`WaitContext` вернулся из-за контекста, вспомогательная горутина продолжает
ждать, пока группа не завершится.

Внутренний `sync.WaitGroup` увеличивается раньше публичного счётчика, а
уменьшается позже него. Поэтому внутренний счётчик никогда не меньше
публичного, и `Wait` не может отпустить раньше времени.

## Производительность

Intel Core Ultra 5 225H, Go 1.27:

| Бенчмарк | нс/оп | аллокаций/оп |
|---|---:|---:|
| `Add(1)` + `Done()` | 34 | 0 |
| то же, `RunParallel` на 14 потоках | 202 | 0 |

## Миграция (с 1.3.x)

| Было | Стало |
|---|---|
| Отклонённый `Done()` всё равно уменьшал счётчик; он оставался отрицательным, и группа ломалась | Счётчик остаётся без изменений |
| Каждый `Add`/`Done` шёл под `sync.RWMutex` | CAS без блокировок |
| `Count() int32` | `Count() int` |
| не было | `Go`, `WaitContext`, `WaitTimeout`, рабочее нулевое значение |
